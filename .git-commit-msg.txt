fix(m5): the drop box accepts the pendrive shape, help lists the new actions, --swap is gone (0.1.0-rc.45)

Exercising the real host showed three defects.

/keeper import F:\keeper-transfer failed because staging expected the vault
directory itself; it now accepts either the vault or the folder that contains it
and says which paths it looked at when neither exists.

The plugin help still listed only the original six actions; it now lists import,
upgrade and undo, and says where the drop box is.

--swap was still accepted although it has done nothing since M1, and the launcher
scripts still passed it; both sides were updated so nothing passes a flag that
does nothing.

Also fixed while closing this: init honours --home (it was hardcoded to the real
home, which is how a stray ~/.dsh/history-keeper.key appeared and was removed), a
generated key with an explicit --store is written next to that store instead of
in another vault's home, and the argument parser no longer reads "no inline
value" as the value null (which had made every --option value read as empty).
